启动任务后，在用户已授权的环境准备、测试上传和预览范围内直接推进。沿用现有平台账号与作品；缺少影响结果的账号、作品或设备信息时集中询问。测试上传可能改变作品草稿，应先只读确认当前作品和版本；无法保留现有草稿时先说明具体影响，再取得针对该影响的决定。

小红书「小工具」与「小程序／小组件」是不同交付路线，本项目是离线 H5 ZIP。不要仅安装小程序开发者工具就认定小工具平台环境准备完毕。以当前账号能访问的小工具入口、官方口令和实际预览方式为准。

目前平台公开说明的基线是 Android 8.1／Chrome-WebView 61、iOS 18.4，执行时复核最新文档。项目 Three.js 0.186 使用 WebGL2，旧内核／GPU 支持是重点兼容风险。缺少 WebGL2 时若只能显示恢复提示，记录「降级提示可用、游戏不能运行」；不能据此判定游戏满足最低平台兼容性。缺少旧环境就写「阻塞／最低基线未证实」，不能悄悄改为只支持新系统。

至少一台／端真机通过只能写「已测设备通过」。若要声称达到最低系统支持，还必须有对应旧系统与内核的证据；否则整体结论保留该兼容性缺口。

## 4. 环境准备顺序

### 4.1 本机盘点与记录

2026-11-10 已观察到：MacBook Pro、M1 Pro、16GB 内存、macOS 26.5.1；磁盘约 86GiB 可用；只有 Xcode Command Line Tools，`simctl` 不可用；已有 adb，设备列表为空；未在标准目录发现 Android Studio、Android SDK／AVD 和完整 Xcode。执行时重新盘点，不能把这份快照当实时状态。

先检查已装工具和活动模拟器，能复用就不重装。记录 macOS、芯片、内存、可用空间、Node/npm/Python、工具版本、工具安装来源。记录现有开发者目录，优先用进程级 `DEVELOPER_DIR` 调用新 Xcode，避免无必要地更改全局开发环境。

16GB 内存建议一次运行一个系统模拟器。先 Android，结束后再 iOS；性能采样时关闭另一个模拟器和重负载任务。安装前重新估算选定 Xcode、runtime、SDK 镜像的实际占用与解压峰值，空间不足只清理本任务新建内容，不清理用户资料。

### 4.2 小红书平台

1. 使用当前可用的小工具 CLI／官方 Agent 接入或创服平台登录态。需要浏览器时按已安装 Skill 的浏览器入口执行。
2. 登录、查询、上传／预览时读取 `webapp-building-pro/modules/xiaohongshu-minitool/cli/GUIDE.md`，先完成版本门禁及真实 `config`、`list`。按当前开发口令确定环境与 source，不能盲用历史 `thirdAgent`。凭证留在工具私有目录。
3. 只读确认「沪上游侠」对应作品、草稿、权限和预览方式；多作品无法唯一匹配时询问。不因列表为空就创建作品；无现有作品时让用户指定是否新建测试作品。
4. 复核 ZIP，按 CLI 当前 dry-run／confirm 协议完成测试上传和预览；记录平台环境、作品匿名标识、上传时间、版本与本地散列映射。
5. 用真实预览入口启动，取得可交付给两端手机的原生预览方式。上传成功、生成二维码、能打开页面、用例通过分别记录。
6. 平台模拟器未提供某项原生能力时，标记「该环境不支持，转真机验证」，不得注入 mock 后标为平台通过。

### 4.3 Android 模拟器

1. 从 Android 官方渠道安装 Apple Silicon 版 Android Studio，或官方 command-line tools＋Emulator＋platform-tools。选择较省心且能完成测试的路线，不要求两套都装。
2. 创建一个 ARM64 AVD；选择工具当前支持的稳定 Android 镜像，记录 API、ABI、分辨率、DPR、RAM 与渲染后端。初始分配约 3GB RAM，按启动实况调整。
3. adb 确认设备已启动；安装／核对浏览器、Chrome／WebView 实际版本与 WebGL2 能力。若使用 Chrome 自定义版本，要确认当前页面真正使用该版本。
4. 通过 `http://10.0.2.2:<端口>/` 访问 Mac 上由最终 ZIP 解压得到的静态站点；运行冒烟并截图。网络地址以当前 AVD 官方网络约定为准，连接失败先诊断服务绑定和端口。
5. 小红书 App 从官方可信渠道安装适配 APK／商店版本，记录版本。官方预览支持 URL／深链时使用；只有二维码时可在授权设备间展示或按官方入口扫描，不能假设 AVD 摄像头可直接扫 Mac 屏幕。
6. 若登录／设备验证／ABI 导致 App 路线不可用，留回执并改做模拟器浏览器测试；Android 小红书容器用例转真机，不绕过安全校验。
7. 不预设 M1 可高效运行旧 x86 Android 镜像。旧内核拿不到兼容镜像时记录 LEGACY 阻塞，选择已有旧真机或经用户明确选择的远端环境；不反复下载无关商业模拟器。

### 4.4 iOS 模拟器

1. 从 Apple 官方渠道安装兼容当前 macOS 的完整 Xcode，只安装本次需要的 iOS runtime。能装 iOS 18.4 再补最低版本，否则先测可用版本并保留差距。
2. 启动一台带安全区的 iPhone 模拟设备，记录设备型号、iOS runtime、逻辑分辨率和 DPR；确认 `xcrun simctl` 可用。
3. 用模拟器 Safari 打开最终 ZIP 的静态站点。通常可访问 Mac 的 `http://127.0.0.1:<端口>/`；执行时确认连通性，不把地址失败误判为应用缺陷。
4. 记录真实 WebKit、WebGL2、字体、存储、画布和音频行为。模拟器鼠标事件不等于三指实触；自动合成事件、系统触摸注入和真人触屏分开标注。
5. iOS Simulator 不具备可直接使用的 App Store 小红书客户端；除非平台明确提供模拟器构建，不寻找或承诺通过普通 IPA 完成小红书容器验收。
6. 若 Xcode 安装受权限／账号限制，完成其他环境并记录阻塞原因、安装到哪一步、下一步具体动作；不改用桌面 Safari 冒充 IOS-SIM。

### 4.5 两端真机

用户提供 Android 和 iPhone 各至少一台，可由用户持机按脚本操作。记录型号、OS、App 版本／build、屏幕刷新率、可见画面尺寸、网络、剩余电量、是否充电、温控／省电模式。Android 能取得 WebView 版本则记录；不能取得就写未知。

优先设备：Android 为现有中低配置设备；iPhone 为现有较旧且符合平台最低系统要求的设备。没有这类机型就先测手头设备，明确覆盖局限。开启必要的本次调试与手机信任，不要求关闭安全机制；系统权限由用户完成。测试使用隔离存档与明确的测试作品／草稿，保留用户原有数据。

## 5. 执行阶段与最先跑的闭环

按以下顺序推进；缺某台手机时继续完成其他可执行环境，不因等待扫码停掉整个任务。

1. **基线**：核对源码、包、现有证据；建立本轮证据目录和测试环境表。
2. **10分钟内可判定的冒烟**：平台导入→可玩→真实保存→关闭重进读回→一次交战→倒地再战→打开声音再静音。若出现白屏、存档丢失、无法操作，先记录阻断问题，不继续做无意义的长时压力测试。
3. **系统兼容**：AND-SIM／IOS-SIM 同包浏览器测试；条件允许则做 Android App 路线。
4. **功能矩阵**：按第6节逐项，模拟器筛问题，真机复核触控、原生桥接和生命周期。
5. **长时与性能**：按第7节，同一版本、画质与路线采样。
6. **问题复验与交付**：对修复后的新包建新轮次，复验失败用例与受影响链路；输出分环境结论和剩余事项。

「10分钟」只表示优先冒烟范围，不承诺平台登录、上传或完整验证耗时。

## 7. 性能与稳定性采样规则

以下数字是本轮拟采用的工程判定线，不是平台官方硬性门槛。开始实测前在报告中沿用；设备实测不达标应如实记录，不能测后改线把失败变通过。

- **固定条件**：收尾优化同包、同设备／App／内核、相同屏幕刷新率和画质；固定档位对照须关闭「自动调节画质」，记录偏好与实际档位，自动开启另测VAL-P06，不混算。流畅档为最低可玩判断。电量建议≥30%，关闭省电，是否充电固定，记录初始热状态。实际设备条件不同则分组，不混算。
- **固定路线**：选择可复现的测试存档与起点，记录坐标／截图／镜头／天气／敌人数量；核心街区移动→一次完整战斗→桥边→动态街区往返→衣橱开关→一次死亡恢复。先预热约60秒；前台连续渲染每轮60秒、3轮；每轮记录有效样本数、p50／p95／p99帧间隔、超过100ms／1000ms帧数。启动、shader初编译、后台和菜单按需绘制单独列出，不能删除坏帧而不报告。
- **暂定可玩线**：流畅档稳态每轮应用提交频率≥30fps、p95帧间隔≤50ms，无>1秒的稳态冻结；屏幕实际掉帧和触控迟滞另看。高刷新率设备与强制帧限需说明。只有视频或目测而无可靠帧数据时，写「主观可玩／性能未量化」，不判量化门槛通过。
- **长时线**：两台真机各30分钟；无崩溃、黑屏、系统低内存终止、存档丢失、持续输入故障；不出现随时间持续恶化且无法恢复的卡顿。发热只记录系统热状态或用户具体感受，不能靠软件猜机身温度。电量变化写起止和环境，不外推整天续航。
- **内存线**：记录可取得的App进程内存、JS heap、GPU资源；三者不能互相替代。试衣／路线重复前后在相同休息窗口比较；每轮持续上涨而不回落则建问题调查。没有原生内存接口时标为未量化，不能通过DevTools heap证明系统内存安全。
- **对照线**：优先用保留的旧字体A包对比本次收尾优化包，关闭自动调节、固定同设备／App／路线／画质／缓存，隔离新旧存档。仍需v0.9.5历史对照时另列。p95相对退化>10%需解释并排查；旧包不可安全运行或场景不同，就不下相对回归结论。已有流畅档三角形下降31%–33%仅为固定画面负担对比；核心调用减少25%的建议目标未达，不据此下手机FPS结论。
- **冷／暖启动**：各3次，分别报可见时间和可玩时间，中位数与最大值；宿主启动、下载与应用初始化能区分就分别记录。没有启动性能承诺，不凭网络慢自动判应用失败；不可恢复的加载失败仍是缺陷。
- **观测工具**：Android优先adb/logcat、可用的WebView调试与系统profile；iOS优先Safari Web Inspector和系统可提供的诊断；App不开放调试时用录像／系统崩溃报告／人工步骤，明确指标缺口。不得为开放调试重签小红书或修改系统保护。

| 状态 | 含义 |
| --- | --- |
