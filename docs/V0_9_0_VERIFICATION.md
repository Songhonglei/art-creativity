# 沪上游侠 v0.9.0 验收报告

日期：2026-11-10。范围按 [完整需求与方案](V0_9_0_REQUIREMENTS_AND_ACCEPTANCE.md) 和 [V3 宠物方案](PET_GAMEPLAY_V3_2026_11_10.md)。

结论：本轮代码、176 项自动化回归、TypeScript、Web／离线 IIFE 构建、离线产物审计与浏览器交互验收通过。小红书平台模拟器、Android、iOS 真机未验，未执行平台上传或送审。桌面手机模拟不能证明真机性能。

## 已交付的行为

- 三宠独立 Lv1–10，出战／待命经验、属性预算、推荐分配、重置和特性选择均接入真实事件；技能仍只按 C／手机一个按钮。
- 橘猫保命、柯基续航、柴犬寻踪与识破；已取消旧方案中的短时连招和轻重击顺序要求。
- 一次自动救援约 0.7 秒扶起，随后给两秒保护；再次倒下以底部卡解释来源与实际伤害，并回到真实营地，保留调查、目标气血和收益。救起提示会结束，倒下卡不混入过期通知。
- 12 套真实低多边形造型：三款原皮肤、九款等级皮肤，各有独立配饰；Lv4／7／10 分宠自动解锁。柯基短尾和犬类口鼻、橘猫胡须、柴犬卷尾保留物种辨识；披风使用贴背弧面。
- 原生 Storage JS API 按客户端版本与实际方法检测启用，普通浏览器兼容 localStorage。读取失败不创建引擎或覆盖旧档；写入按 key 串行并等待回执，失败保留当前选择、可重试。
- v1／v2 旧档一次迁移到 schema v3，原共享训练1／2／3对应三宠1／4／7，保留资源、补点、解锁皮肤，初次迁移仍穿原皮肤。

## 构建与产物

执行：`npm test -- --reporter=dot`、`npm run build`、`bash scripts/build-tool.sh`；另用 builder 的 Python 审计检查最终 ZIP 内容。

- 176项测试全部通过，8个测试文件；未跳过失败项。
- 最终ZIP约2.18 MiB，18个文件；`index.html`位于根目录，经典`./app.js`，全部资源随包；ZIP每个文件与同版H5字节一致。
- `mini_tool.json`为`is_high_consumption_scene:false`；本轮使用普通主线程Three.js与可见Canvas，无实际Worker、OffscreenCanvas、WASM或Unity/Cocos运行路径。
- `output/沪上游侠-v0.9.0-小红书小工具.zip`与通用文件名ZIP内容相同；本地预览为`http://127.0.0.1:4174/?v=0.9.0`。
- 构建有两项建议提示：Web单chunk大于500kB；ZIP略超建议2MiB，但小于10MiB上限。包体主要为本地中英文字体，宠物皮肤采用程序几何，无新增图片／模型下载；未为压体积牺牲字体和模型。
- 版本、准确字节数与SHA256见[产物记录](evidence/v0.9.0/artifact-checks.json)。

## 性能与验收边界

每套宠物合批后约8–14个网格、3,108–5,988个三角形；相较原皮肤最多增加约5个网格、2,824个三角形。同一时间仅一只出战模型可见，已见皮肤缓存上限12，预览只在操作／尺寸变化时绘制，关闭后释放GPU资源。

生产H5在桌面Chromium、390×844手机模拟、low画质的一个城区帧采样为189 draw calls／100,078三角形／173几何／21纹理。**整个城区的低档绘制量仍高于小工具保守预算**，没有Android／iOS设备FPS与内存数据，不能据此确认低端机流畅度。手机布局、触控通过与真机性能通过分别报告。

[在线容器文档](https://miniapp-sandbox.xiaohongshu.com/minitool/doc)在本轮获取成功（HTTP200），本地缓存按其中Storage公开契约和9.46版本判断实现；没有接入本轮范围之外的原生能力。JavaScript为Chrome61／ES2017构建目标，新布局有Grid gap基线，实际Chrome61／旧WebView CSS兼容未实测。Three.js场景需要可用的WebGL2，失败时给重新加载提示。

后续平台验收：上传同一ZIP后，分别完成创服平台模拟器、Android真机扫码、iOS真机扫码；原生缓存、关闭／重进恢复、掉帧、发热与内存需在这些环境中确认。本轮未上传、未送审，不能将浏览器或mock写成平台验收通过。
