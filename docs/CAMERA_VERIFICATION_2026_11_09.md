# 角色环绕镜头验证记录

本次实现球面环绕、水平 360°、有限俯仰、滚轮／双指缩放、镜头归位及有高度的场景避障。手机摇杆、场景手势和动作按钮分别管理手指；支持保持左手移动时用右手环顾，或再增加一根场景手指缩放。锁定时手动操作优先，松手 1.6 秒后跟回目标。

## 自动化与构建

- `npm test`：82 项通过，其中 21 项为新增镜头与手势回归。
- `npm run build`：TypeScript 与普通 Web 构建通过。现有的大 JS 分块体积提示仍存在。
- `bash scripts/build-tool.sh`：同版离线 H5 与 ZIP 构建通过，目录审计通过。
- Python 最终 ZIP 内容审计通过，17 个文件；ZIP 内文件与 `dist-tool` 逐字节一致。
- ZIP 大小 2,263,191 字节（约 2.16 MiB），低于 10 MiB 上限，高于 2 MiB 建议值。
- SHA-256：`cf7326edcdad293a1257211a435f07dbe60b56ffbd9cce5d4d0f92a7932e9227`。

## 浏览器交互

使用 macOS 上的 Chromium，通过浏览器原生多点触摸注入检查：

- 左手摇杆移动、右手环顾同时生效；只移动摇杆手指不会转镜头。
- 左手移动加两根场景手指缩放同时生效；缩放不旋转、不攻击。
- 触摸取消后摇杆停止、场景手指归零；开菜单后暂停并清除输入。
- 桌面拖动不攻击；镜头归位恢复默认距离与俯仰。
- 实际锁定场景中，手动环顾优先；抬手后保留宽限，再恢复跟随。
- 320×568、390×844、844×390、1024×768 视口均无横向溢出；摇杆、出招与归位控件均在视口内，触摸目标不小于 44×44。
- 注入顶部 44px、底部 34px 安全区后，顶部信息与底部控件保留相应空间。

最终 `dist-tool` 另用独立页面验收：在禁止外部网络、内联脚本与 Worker 的 CSP 下，经典 IIFE 包可启动；原生触摸环顾、缩放、归位通过，字体加载完成，请求均为包内资源。另一次兼容性检查禁用了 `queueMicrotask`、`Array.flatMap`、`ResizeObserver`、`OffscreenCanvas`，页面启动与运行期间未捕获脚本错误；这属于缺失 API 检查，不等于运行于 Chrome 61。

## 多角度避障

五处可行走位置 `(0,20)`、`(-24,31)`、`(-14,38)`、`(7,-31)`、`(310,310)`，分别覆盖开阔街道、老弄堂、近建筑街道和动态街区。每处组合 24 个水平角度、3 个俯仰角、3 档距离，共 1,080 组：

- 镜头坐标均有效，未进入建筑碰撞体。
- 287 组因遮挡或地面安全距离发生收缩。
- 单元测试另覆盖窄墙、墙角余量、低矮柜台、越过屋顶、圆形塔柱、地形中段与桥面，以及插值路径再次避障。

开发浏览器中连续执行 2,000 次镜头更新，平均约 0.019ms／次。该数字只代表此次桌面环境的镜头 CPU 计算，不含渲染与街区生成，也不代表移动端帧率。

## 验证边界

避障使用有高度的建筑包围盒、柱体和地面采样，优先控制移动端开销；树冠、桥梁细缆、装饰构件等没有逐三角形碰撞。实际转过 180° 的便利店碰撞范围也已修正，车辆与店铺补齐高度，避免被当成无限高墙。
